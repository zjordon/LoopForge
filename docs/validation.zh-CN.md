## 真实模型覆盖

所要求的 `deepseek-v4.1-flash` 模型以验收账号自己的 CodeBuddy 凭据与匹配的认证环境运行。源码与测试夹具中不存储任何凭据。

- 一个 Agent 节点写出了声明的产物；随后的脚本检查了文件内容。套件检查了 token 用量、遥测与产物下载。
- 一条完整的交付 SOP 规划了变更、修复 Python 代码、独立评审、通过三个真实测试、等待人工审批并生成交付摘要。最后的脚本重跑测试并核对交付未改变已验收的代码哈希。四个模型角色均记录了真实 token 用量。
- 已完成的运行做了 AI 评测。
- 助手回答了一个只读的项目问题，并以 SSE 流式返回。
- 浏览器提交了一条真实的首页工作台消息，观察到完整回复，重载并检查了服务端会话。
- 通过真实浏览器 UI 完成了需求分析。
- Classic 与 Portable 本地工作流各自在真实 CodeBuddy 进程中于一次性项目内运行，修复夹具、通过测试并保存完成状态与交付产物。

这些测试覆盖所提供的 CodeBuddy 模型。Codex 与 Claude 执行器有命令/协议与凭据边界测试；未以独立的服务商凭据实测其付费服务。

## 检查覆盖的修复

首页输入框现在接受模型配置前的草稿，链接到凭据字段，并在凭据保存后更新发送可用性。从设置返回时保留草稿。凭据相关的浏览器测试禁用 trace 与截图。

头像回退与 Bot 刷新使用与既有内容安全策略兼容的外部 JavaScript 处理器。整视图浏览器检查拒绝运行时与 CSP 错误。显式配置的助手模型按其真实模型 ID 展示。

全新 MySQL 安装在目录安装前显式应用上游可观测性生成列基线。初次与重复安装均经核验；应用启动仍不执行数据迁移。

第三方声明维护于仓库根目录。打包时生成本地分发声明，而非维护第二份源码副本。本地组件的入口文档与共享项目策略保持合并。

首次访问无账号的安装时在浏览器中创建管理员；此后登录页提供自助注册，除非 `AGENTFLOW_ALLOW_SIGNUP=false`。首页展示可关闭的上手清单，跟踪模型 Key、项目、首次对话、首次运行与仓库连接；未配置 Key 时输入框显示醒目提示。欢迎项目 seed 不再要求 `admin` 账号，安装器会等待 API 就绪后再应用 seed（旧版净装曾因缺少 `run_telemetry` 表失败）。没有照片服务时，头像在本地渲染而非返回 502。

清单打开的仓库弹窗此前没有提交处理，保存会整页刷新；现在正常保存。仓库写入此前接受任意已登录用户；现在要求项目所有者或平台管理员。
