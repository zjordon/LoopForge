# LoopForge - 使用指南

> 生成时间: 2026-11-15
> 面向自托管部署的管理员与团队成员。架构与机制背景见同目录《架构分析》《运行机制分析》；Windows 用户请先读《Windows 兼容性分析》。

## 1. 快速开始

### 1.1 环境要求

| 要求 | 版本/说明 |
|------|-----------|
| 操作系统 | Linux 或 macOS（Windows 需 WSL2 + Docker Desktop，在 WSL 内操作） |
| Git | 任意近期版本（先 clone 本仓库） |
| Docker + Compose 插件 | 安装器会检查并可选代装（apt/dnf/yum/brew；Compose 为官方校验版） |
| Python 3 + curl | 安装器依赖（可代装） |
| 网络 | 需访问 GHCR（或镜像站）拉取 `ghcr.io/tencent/loopforge:0.3.8` |
| 源码开发（可选） | Go 1.26.11+、Node.js 22+（chatbot 构建） |
| LoopForge Local（可选） | Node.js 20+、Python 3.8+、编码助手宿主（Claude Code/CodeBuddy/Codex/Cursor/Pi/DSH/Hermes） |

### 1.2 安装

```bash
git clone https://github.com/Tencent/LoopForge.git
cd LoopForge
./start.sh                 # 拉 GHCR 发布镜像, 起 mysql + platform, 生成 .env 密钥, 装 seed
# ghcr 慢时: MIRROR=ghcr.nju.edu.cn ./start.sh
```

安装器产出：`.env`（权限 0600，含随机 DB 密码与 `AGENTFLOW_SESSION_SECRET`）、docker 卷 `mysql-data` 与 `platform-data`、数据目录 `LOOPFORGE_DATA_DIR`（默认 `./.data`，含 home/workspaces/conversations/cli）。服务监听 `0.0.0.0:8090`。

浏览器打开安装器打印的地址，**创建的第一个账号即平台管理员**。首次开放前建议把安全组限制到运维 IP。

### 1.3 快速运行

```bash
./start.sh logs             # 跟随日志        ./start.sh stop     # 停止
./start.sh restart          # 重启 platform   ./start.sh down     # 删容器保数据卷
./start.sh pull             # 升级: git checkout vX.Y.Z 后刷新镜像并重建
./start.sh dev              # 改为源码构建(compose.dev.yaml, loopforge-platform:local)
./start.sh release          # 从源码构建切回发布镜像
```

**无 API key 试玩**：新账号自动加入 demo 项目 → Templates → 「Platform check · script & approval」→ Run SOP → 在 Needs review 里批准，观察一个真实的 script+human-gate 流程跑完。

**源码开发**：`bash scripts/dev.sh` 只起本仓库 MySQL、构建平台、provision admin（密码写 `.local/admin-password`）、应用观测列与种子、8090 起服务。

## 2. 配置说明

### 2.1 配置文件

`.env`（由 `scripts/configure.sh` 生成；已存在的环境变量优先生效，进程会向上查找 4 层目录的 `.env`，`cmd/agentflow/main.go:36-75`）

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `AGENTFLOW_MYSQL_DSN` | 自动拼装 | MySQL 连接串（唯一数据源；外部 MySQL 直接填此项） |
| `AGENTFLOW_SESSION_SECRET` | 随机 32B | 会话签名密钥，**必须跨实例/重启稳定** |
| `AGENTFLOW_HTTP_PORT` / `LOOPFORGE_MYSQL_PORT` | 8090 / 33315 | 对外端口（MySQL 仅绑 127.0.0.1） |
| `LOOPFORGE_BIND` | 0.0.0.0 | 监听地址；本机使用设 127.0.0.1 |
| `LOOPFORGE_DATA_DIR` | ./.data | 工作区/会话/CLI 数据根（容器同绝对路径 bind mount） |
| `AGENTFLOW_AUTH_REQUIRED` | true | 关闭仅限内网测试 |
| `AGENTFLOW_ALLOW_SIGNUP` | true | 公网部署务必设 false，改由管理员开账号 |
| `AGENTFLOW_SECURE_COOKIES` | — | HTTPS 终止在反代时设 true |
| `AGENTFLOW_GITHUB_CLIENT_ID` | 内置 OAuth App | 自建 GitHub OAuth App（Device Flow）时覆盖 |
| `LOOPFORGE_IMAGE` / `LOOPFORGE_PULL_POLICY` | compose pin / missing | 镜像覆盖（支持 `@sha256:`）与拉取策略 |
| `MIRROR` | — | ghcr 镜像站（如 ghcr.nju.edu.cn），一次性变量 |
| `AGENTFLOW_ROLE` | all | api / worker / all 分离部署 |
| `AGENTFLOW_CONTROL_TOKEN` `AGENTFLOW_CONTROL_URL` `AGENTFLOW_WORKER_URL` | — | worker 分离时的控制通道 |
| `AGENTFLOW_PLATFORM_MCP_URL` `AGENTFLOW_MCP_TOKEN` | — | 沙箱可达的平台 MCP 地址与令牌 |
| `AGENTFLOW_INSTANCE_ID` `AGENTFLOW_RUN_LEASE_TTL` `AGENTFLOW_DRAIN_TIMEOUT` | 自动 / 30s / 120m | 实例标识、run 租约 TTL、停机排水上限 |
| `AGENTFLOW_LOCAL_SANDBOX` `AGENTFLOW_DOCKER_NETWORK` `AGENTFLOW_ISOLATED_IMAGE` | docker / 自动 / 平台镜像 | 沙箱行为（默认兄弟容器） |
| `AGENTFLOW_GIT_SSH_KNOWN_HOSTS` | — | Git SSH 的 known_hosts 绝对路径 |
| `AGENTFLOW_ASSISTANT_MODEL` `AGENTFLOW_ASSISTANT_MODELS` | — | CodeBuddy 模型目录 |
| `AGENTFLOW_TRUST_IDENTITY_HEADERS` `AGENTFLOW_IDENTITY_HEADER_SECRET` | — | 企业网关头登录（务必同时设 secret） |
| `AGENTFLOW_RUNNER_BINARY` `AGENTFLOW_GATE_MCP_BINARY` | 镜像内置 | runner 二进制下发地址（支持 `{os}/{arch}`） |
| `AGENTFLOW_GIT_CLONE_STALL_TIMEOUT` 等 4 项 | 5m/10m… | clone 与 docker build 的停滞/总超时 |

完整变量随版本演进，以 `docs/deployment.md` 与 `compose.yaml` 注释为准。

### 2.2 运行时凭据（在 UI 配置，不进 .env）

- **模型 key**：个人设置里按执行器（CodeBuddy/Codex/Claude Code/OpenCode/Cursor CLI/Antigravity/Kimi Code/Pi/DSH/ZCode）填 key 与可选 Base URL；管理员可配**平台共享 CodeBuddy Key** 供无 key 成员使用。
- **GitHub**：个人凭据 → Connect GitHub → 复制 PIN → GitHub 确认（内置 OAuth App，device flow，`repo` scope）；PAT 手填仍支持。
- **Git SSH**：管理员放 known_hosts；每人把自己的私钥按 host 加到「Git SSH keys」，GitLab/Gitea/Gogs 等都走这条路。

## 3. 主要功能

### 3.1 与 Main Bot 聊天（Chat 工作台，中文界面）

**说明**: 在 composer 输入需求，`@` 引用角色/技能/需求/SOP/仓库，逐会话选执行器、模型与权限模式。平台按需开**对话工作区**（Docker 沙箱 + 仓库检出），Main Bot 调项目角色作为子代理干活；回复期间消息可排队或 *Steer* 插队；产物在侧栏预览/下载；可一键推分支开 PR/MR。

### 3.2 运行 SOP（可复用交付流程）

**说明**: Templates 页从内置 4 套 SOP（后端/前端/修 bug/产品提案）复制到项目，在画布上编排 Agent/Script/Human-gate/Sub-SOP/Preview 节点与失败回边，发布版本。Run 页有实时节点状态、工具轨迹、worker 日志、每节点产物；到人工门禁时进「Needs review」统一收件箱，可批准、加上下文重跑该步、或打回上游任意节点（含取消后复活的兄弟分支）。Main Bot 也能在聊天里启动/暂停/接管 SOP run。

### 3.3 AI 定时任务与市场

**说明**: 周期性 agent 任务（完整工作区 + SOP + MCP 权限），市场提供带版本与业务参数的任务模板，可按新需求自动派发 SOP。

### 3.4 接入个人执行机（Runner）

**说明**: 让任务跑在自己机器/内网机器上（用自己的工具与仓库凭据）：执行器页面拿短时绑定码 → 目标机器执行平台下发的 `/runners/install.sh`（或手动装 `agentflow-runner`）。执行机只发出站连接（HTTPS 长轮询 + WSS 控制通道）。

### 3.5 LoopForge Local（不搭服务的个人用法）

```bash
# 在目标项目里, 例如 Claude Code
npx -y loopforge-cli@latest install claude
# 然后在 Claude Code 中运行
/start-devflow "<你的需求>"
```

支持 Claude Code/CodeBuddy/Codex/Cursor（Classic 版）与 Pi/DeepSeek Harness/Hermes（Portable 版）；产物落 `artifacts/{task_slug}/`。

## 4. API 接口

完整参考见 `docs/api/`（按领域拆 5 个文档，另有 `docs/api/openapi.yaml`）。约定：UTF-8 JSON、请求体上限 2 MiB、列表全量返回；认证用登录 Cookie（浏览器）或个人 Token `Authorization: Bearer afp_xxx`（REST/MCP，明文只显示一次）。

| 接口组 | 方法与路径示例 | 说明 |
|--------|----------------|------|
| 通用 | `GET /api/health`、`GET /api/capabilities`、`GET /api/bootstrap`、`POST /mcp` | 健康、能力契约、初始化目录、MCP Streamable HTTP |
| 认证 | `POST /api/auth/password`、`/api/auth/github/device|poll`、`/api/auth/tokens` | 密码登录、GitHub device flow、个人 token 管理 |
| 协作 | `/api/projects`、`/api/repositories`、`/api/issues`、`/api/tasks` | 项目、仓库、需求/Issue、跨实例任务 |
| 目录 | `/api/agents|rules|skills|mcp-servers|executors|dockerfiles|environments|sandboxes|workflows` | 角色与 SOP 注册表 |
| 运行 | `POST /api/runs`、`/api/runs/{id}/stream`(SSE)、审批/重试/取消、`/api/runs/{id}/eval` | SOP run 全生命周期 |
| 助手 | `/api/assistant/*`（chat SSE、会话、定时任务、审批） | Main Bot 与定时任务 |
| 执行机 | `/runners/install.sh`、`GET /runners/connect`(WSS)、claim/lease/events | 机器面（绑定码/session token，不走网关登录） |

```bash
export AGENTFLOW_URL=http://127.0.0.1:8090
export AGENTFLOW_TOKEN='afp_xxx'
curl -H "Authorization: Bearer $AGENTFLOW_TOKEN" "$AGENTFLOW_URL/api/health"
```

## 5. 常见问题

**Q: 必须有模型 API key 吗？**
A: 不用。demo SOP 只有脚本节点和人工门禁。聊天和 Agent 节点才需要所选执行器的 key（自带凭据，平台不含模型费用）。

**Q: 必须连 GitHub 吗？**
A: 不用。文档生成、新项目在任务工作区完成；要改现有仓库/开 PR 时再连 GitHub（或对 GitLab/Gitea 等配置 Git SSH + 托管 API token/MCP 做 Issue/PR 自动化）。

**Q: 用 Chat 还是 SOP？**
A: 探索迭代用 Chat；要把固定阶段、检查与签-off 沉淀成每次都一样的交付流程就用 SOP。两条路都归到同一个「需求」追踪交付与成本，Main Bot 也能接管 SOP run。

**Q: 能暴露公网吗？**
A: 面向可信团队设计（登录用户可读全部项目数据）。公网必须：HTTPS 反代（转发 WebSocket/SSE）、`AGENTFLOW_ALLOW_SIGNUP=false`、`AGENTFLOW_SECURE_COOKIES=true`、限制端口访问；不要做多租户隔离用。

**Q: Docker socket 挂进容器安全吗？**
A: socket 等价于宿主 root。平台把每个任务放进沙箱容器并只允许管理员挂宿主源码路径，但能跑 SOP 的人就能在这台机器上执行容器代码。不挂 socket 的方案：去掉 compose 里的 docker.sock 与 `AGENTFLOW_LOCAL_SANDBOX`，另接带 Docker 的 worker/执行机。

**Q: 和 Dify/n8n 有什么区别？**
A: 那些是通用 AI/自动化流构建器；LoopForge 专为「用编码代理交付软件」设计：实现/评审角色分离、带真实仓库的 Docker 沙箱、GitHub 交付、人工验收门禁与 run 证据。

**Q: 升级怎么做？**
A: `git fetch --tags && git checkout vX.Y.Z && ./start.sh pull`。`start.sh pull` 会重建变更容器并重放观测列/种子 SQL；个别数据迁移需按 `docs/deployment.md`「Which migrations an upgrade needs」手工执行。

**Q: Windows 能用吗？**
A: 平台服务建议在 Linux/macOS 或 Windows 的 WSL2 内部署（见《Windows 兼容性分析》）；LoopForge Local 的 `npx` 入口对 Windows 原生友好。
